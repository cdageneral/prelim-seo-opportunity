# v7.581 — Sort "Other" into new categories; the Competitor Gap card says what it leaves out (2026-10-21)

Wayne, on Sonobello: *"it only shows 251 keywords in competitors does that look right?"* After the re-file, 473 competitor keywords (741K searches/mo) were sitting in the hidden "Other" bucket, more volume than the 251 that counted. Most were body-concern searches (hip dips 90.5K, muffin top, beer belly, how to get rid of lower belly fat). They landed there because the filer can only use categories that already exist, and Sonobello had none for them. Wayne chose to add a category and re-file Other into it. That needed a Constitution amendment: **III.1e v0.43**, only the user creates a new category, through a reviewed proposal.

- **Sort into categories** (Keyword Selection, Step 2): a new button on the top-level **Other** row. It shows even while Other is unticked. It runs the v7.573 split review on Other. The AI proposes new **top-level** categories for the keywords that belong on the site, reusing an existing category when one fits. Everything else stays in Other. Each group can be set to **Add** or **Leave**. Only the groups you Add are created. A new category is in scope as soon as it exists, gets its own page match, is kept on the next Refresh Analysis (taxonomy anchor), and is logged in the merge log.
- Brand-named groups are rejected (III.1). A one-keyword group stays in Other. A group named like an existing top-level category reuses that category. Every keyword is placed exactly once.
- Keywords a sort leaves in Other are marked as reviewed, so the next run reads the next keywords instead of the same ones again. When Other holds more than one run can read, the panel says how many remain.
- **Competitor Gap card**: when the card leaves keywords out, the sub-line now says so: "N more in unticked categories · M awaiting categorization". The counts come from the same pool builder with only the hiding rule toggled. A bare 0 no longer hides 2,105 stored rows (what happened on Sonobello on 10/20).
- **Step 3 status** says "loading…" while the uploaded rows are still arriving, instead of "required". Competitor rows live only there, so for a few seconds the step looked unfinished.
