# v7.367 — Google Rank Authority panel: real backlink-authority signals (2026-07-14)

## Why
Wayne is building an authority-bridging workflow: measure the authority gap between the client and its competitors, then (v7.368, the Authority Calculator panel) estimate how many campaigns — one campaign = one guest-blog placement = one referring domain, Wayne's stated assumption — are required to bridge it at the domain, category, or targeted-page level. The Google Rank Authority nav item existed but rendered "Coming soon". This release builds the measurement half: the panel that pulls and stores the real authority signals the calculator will consume. The factor model follows the Ranking Gap Diagnostic methodology (GEO/Gap_Model_Methodology_v0.1.md): raw link counts alone mislead — quality distribution, anchor profile, topical relevance, and brand/entity demand are what separate ranking pages from non-ranking ones.

## What shipped
- **`app/api/projects/[id]/authority-scan/route.ts` (NEW)** — GET returns the stored scan; POST `{dryRun:true}` returns the plan + estimated Semrush units **without spending any**; POST runs the scan as streamed NDJSON progress (done/total/step label/ETA). Per domain (client + every configured competitor): `backlinks_overview` (Authority Score, total backlinks, referring domains, follow/nofollow), `backlinks_ascore_profile` (referring domains per AS value → exact TS quality-tier rollups AS≥10/30/50), `backlinks_anchors` (top N by referring domains), `backlinks_categories_profile` (topical categories of referring domains), and `phrase_this` on the brand phrase (real entity demand). Anchor/category row limits are user-visible, editable choices confirmed in the dry-run step (Const I.6 — anchors cost 40 units/row; an unbounded pull on a large domain would be millions of units). Snapshot persists on the **project row** (`projects.authority_snapshot`, ADD COLUMN IF NOT EXISTS in the list + [id] + scan routes per the v7.268/v7.327 column lesson) so it survives the full keyword reset, like the taxonomy anchor. Each report failure is recorded per domain as an honest gap (I.5) — never a fabricated zero.
- **`lib/apis/semrush.ts`** — backlinks report client: these reports live on `https://api.semrush.com/analytics/v1/` (not the classic base). All pulls feed the v7.225 usage ledger.
- **`lib/usage/record.ts`** — verified rates added to `SEMRUSH_RATES` (developer.semrush.com/api/seo/backlinks/, checked 2026-07-14): `backlinks_overview` 45/request, `backlinks_anchors` 40/line, `backlinks_ascore_profile` 1/line, `phrase_this` 10/line. `backlinks_categories_profile` has **no published rate** — deliberately left out of the table so it records at the assumed default **with** the `rate_assumed_default` meta note (an assumed rate is never passed off as verified).
- **`components/brief/GoogleRankAuthoritySection.tsx` (NEW)** — scan flow: Run scan → dry-run cost estimate with editable limits → confirm → determinate progress bar + ETA (IV.2). Signals: client-vs-competitors comparison table (Authority Score labeled **modeled**, referring domains, AS≥10/30/50 quality tiers, follow share, brand demand/mo), referring-domain gap ratios computed from the real rows, per-domain anchor cards with a **brand-anchor lower bound** (deterministic brand-token rule, disclosed on-panel, computed from the pulled top-N anchor rows only), topical categories (labeled as Semrush's modeled classifier), and a methodology/provenance footer (index, date, what's modeled vs measured). In-place rescan CTA + last-scan timestamp (IV.4/IV.5); orbit-* tokens only (IV.6).
- **`app/projects/[id]/page.tsx`** — renders the section for the `authority` nav item (independent of a keyword analysis — domain signals exist without one), wrapped in the IV.1 scroll root; removed `authority` from the coming-soon fall-through.
- **`db/schema.ts`**, **`app/api/projects/route.ts`**, **`app/api/projects/[id]/route.ts`** — `authority_snapshot` / `authority_snapshot_updated_at` columns + ensure-column coverage.

## Constitution
**I.1/I.2** — every on-screen count is a crawled Semrush index row, date-stamped; provenance footer names each report. **I.5** — failed pulls render as honest gaps with the error visible. **I.5a** — Authority Score and the Semrush category classifier are modeled and labeled as such on-panel; quality tiers are exact TS rollups of real rows on the modeled AS scale, labeled. **I.6** — no silent caps: the dry-run step surfaces the row limits and estimated spend for the user to set and confirm. **IV.1/2/4/5/6** — scroll root, determinate progress + ETA, in-place rescan CTA, last-scan timestamp, dual-theme tokens.
